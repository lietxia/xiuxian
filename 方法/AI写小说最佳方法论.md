## 1. 核心理念

### 1.1 黄金法则

**你不是在让AI替你写小说，你是在用AI放大你的创作力。**

- **Authors Guild 核心原则**: 如果你声称自己是作者，不要让AI取代你独特的声音、思想和创造力。
- **Mindhacker 五项原则**: 通感练习 → 明确愿景 → 设定边界 → 逐步构建工具集 → 保持创作主权
- **2026年行业共识**: 最好的作者不是问"该不该用AI"，而是问"如何用AI而不失去我的声音、原创性和灵魂"

### 1.2 人机协作光谱

| 阶段 | 人负责 | AI负责 |
|------|---------|--------|
| 灵感构思 | 核心创意、情感内核 | 头脑风暴、扩展可能性 |
| 大纲规划 | 结构决策、主题把控 | 生成多版本、填充细节 |
| 初稿写作 | 关键场景、风格定调 | 批量产出、克服空白页 |
| 编辑润色 | 声音保留、主线把关 | 一致性检查、语法修正 |

### 1.3 核心成功公式

```
成功 = (人类创意 × AI效率) + 一致性系统 - AI味噪音
人类创意 = 情感真实 + 生活经验 + 独特声音
AI效率   = 快速生成 + 多版本 + 一致性检查
一致性系统 = 角色档案 + 世界规则台账 + 连续性台账
AI味噪音 = 模板化表达 + 逻辑漏洞 + 声音漂移
```

## 3. 提示工程核心方法

### 3.1 层级化提示结构（Layer Cake Method）

```
LAYER 1: 项目简报   (类型、受众、风格)
LAYER 2: 创作约束   (POV、时态、字数、show don't tell)
LAYER 3: 大纲/节拍  (章节结构、场景节拍、情节弧线)
LAYER 4: 上下文注入  (角色档案、世界设定、连续性台账)
LAYER 5: 风格表     (语调、词汇偏好、句式节奏)
LAYER 6: 质量门     (一致性检查、逻辑验证、风格审查)
```

### 3.2 项目简报提示模板

```
你是一位畅销书作家和开发编辑，请为一部完整的小说创建项目简报。

书籍类型：[小说/非小说]
流派/主题：[例如：奇幻浪漫]
目标读者：[写给谁看]
目标：[读者获得什么体验或转变]
独特角度：[它与众不同的地方]
篇幅：[约XX字]

输出：1) 一句话高概念 2) 读者画像 3) 核心承诺 4) 语调/风格摘要 5) 成功标准
```

**提示**: 保存最终简报到一个文档，每个章节提示都要复用。

### 3.3 章节提示模板（JP LeBlanc 实战验证）

```
## 静态组件 (写入系统消息)
你是一位畅销小说家，擅长创作读者喜爱的故事。
始终遵循以下规则：
- 使用过去时态和美式英语拼写，使用主动语态
- 始终遵循"展示而非告知"原则
- 每场景输出800-1200词

## 世界设定数据 [粘贴世界设定]

## 角色设定数据 [粘贴角色档案]

## 写作风格指南 (约6,000词) [语调、句式、偏好词汇、禁忌词清单]

## 动态组件 (每场景重新生成)
### 前4个场景 [粘贴最近4个场景摘要]
### 完整故事进展 (1,000-80,000词) [粘贴截至目前的故事全文]

## 创意组件 (每场景定制)
### 场景描述 [精确的动作、涉及角色、位置、情感设定]
### 额外指令 [AI经常遗漏的特殊指导]
```

### 3.4 散文写作提示模板

```
用以下细节写一段600词的章节内容：

流派：[填入流派] 语调：[填入语调] 视角：[填入人称/时态]
场景设定：[填入场景] 关键角色：[填入角色详情]
风格：[填入风格描述] 故事节拍：[填入节拍]

额外约束：
- 避免"总而言之"、"不可否认"等AI过渡词
- 使用强动词而非副词
- 每个角色要有独特的声音
- 场景结束时留下未解决的张力
```

### 3.5 场景简报法（对抗"剧情溢出"）

**问题**: AI上下文塞入太多角色和情节线时，发生"剧情溢出"——角色混淆、情节提前、动机漂移。

**解决方案**: 两步骤场景简报法

**步骤一：隔离式场景简报** — 为每个场景创建独立、自包含的写作指令。目标是：只看简报就能写出完整场景，无需参考主大纲。

```
提示词：
"请根据我附上的故事信息（前提、角色、设定、大纲），为我的场景填写以下简报模板。
该简报应包含写出完整场景所需的所有信息，无需参考其他故事文档。"
```

**场景简报模板**：
```
## 场景简报

章节标题：[工作标题]
场景中的角色：（只列出本场景实际出现的角色，附核心动机）
叙事视角：[人称/时态/POV角色]
情节上下文：[本场景前刚发生了什么？一段简短的摘要]
主要事件：[关键行动1] [关键行动2] [关键行动3]
冲突和张力的来源：
开场钩子：
结尾钩子（衔接下一场景）：
语气和节奏：[紧张急促 / 缓慢沉思 / 对话驱动 / 动作驱动]
```

**步骤二：零上下文的纯净生成** — 清空上下文，开全新会话，只喂入场景简报。

```
提示词：
"请阅读以下写作指令。仅使用这些指令，写出场景。
用第三人称、过去时，从[角色名]的视角写。"
```

> 注意：务必重复叙述视角。如果AI搞错了视角，后期修改非常痛苦。

### 3.6 时间线感知提示（解决"未来剧透"）

AI最隐蔽的问题：写第5章时"透露"了第20章才会发生的事。

```
[时间线感知]
处理大纲时，将事件分类为：

过去/现在(已完成章节)：这些事件已经发生。受影响的角色携带那段历史。

未来(未写章节)：仅供一致性参考。用于保持角色塑造一致、埋设伏笔、避免矛盾。
不要将未来事件视为当前现实。

写场景前问："这个事件在已写章节中是否已经发生？"
如果否，那么：
- 相关角色处于事件前的状态
- 该事件未影响当前行为
- 对此事件的引用仅为伏笔，而非过去时
```

## 4. 大纲与结构

### 4.1 五种大纲方法对比

| 方法 | 适合 | 核心结构 | AI辅助方式 |
|------|------|---------|-----------|
| **三幕结构** | 初学者 | 设定→对抗→解决 | AI生成每幕关键事件 |
| **Save the Cat** | 类型小说 | 15节拍表 | AI识别每节拍位置 |
| **英雄之旅** | 奇幻/冒险 | 12阶段 | AI映射角色成长阶段 |
| **大纲法** | 自定义 | 从Story Bible生成逐章大纲 | AI从细节生成大纲 |
| **分幕结构** | 复杂叙事 | 8分幕 | AI优化幕间转折点 |

### 4.2 推荐大纲流程

- **Step 1 前提 (5分钟)**: 2-3句话描述流派、主角、核心冲突、设定
- **Step 2 生成大纲 (10分钟)**: AI创建逐章大纲，手动审查重组
- **Step 3 扩展节拍 (15-30分钟)**: 每章2-3个场景节拍，确保推进情节或角色发展
- **Step 4 审查迭代**: AI多版本 → 手动融合最佳部分 → 迭代

### 4.3 层级化大纲结构

```
Tier 0: 一句话前提 → "一个退休的冷战密码学家收到一封加密信..."
Tier 1: 4-5段梗概 → 三幕结构/救猫咪节拍表
Tier 2: 章节级大纲 → 每章2-4句：POV角色、地点、变化
Tier 3: 场景级节拍 → 每个场景：事件、角色、情感色调、重要细节
```

**最佳实践**: 先用GPT-5生成Tier 1/2（逻辑强），再用Claude Opus扩展为Tier 3（散文感强）。第一版永远是泛化的，第四版才是你的书。

### 4.4 连续性台账系统

每章提示都粘贴的台账模板：

```markdown
## 故事连续性台账

### 角色状态追踪
CHARACTER: [角色名] — 状态: [位置/情感/目标], 最后出现在: [章节]

### 世界规则台账
WORLD RULE: [规则] — 确立于: [章节] | LIMITATION: [限制] — 例外: [描述]

### 资源台账
RESOURCE: [角色/团体] 拥有 [资源], 获得/失去于: [场景], 当前状态: [状态]

### 未解之谜
MYST-001: [谜团]. 状态: 未解. 当前线索: [已知事实]
```

### 4.5 "But and Therefore" vs "And Then"

- ❌ **"And Then"** (平淡): 角色做了A，然后做了B，然后C发生了
- ✅ **"But and Therefore"** (冲突驱动): 角色做了A，但是B阻止了，因此C...

```
"国王去世了，然后王后也去世了" → 平淡
"国王去世了，但王后本应坚强统治，因此她秘不发丧..." → 有冲突
```

### 4.6 场景最小可行结构

每个场景必须包含: 1) **目标** — 角色的场景目标 2) **冲突** — 谁/什么阻止他 3) **变化** — 结束时发生了什么变化 4) **悬念** — 什么让读者想看下一场景

### 4.7 "逐场景不逐章"规则

一次只写一个场景，而不是一个章节。一个场景 = 一个地点 + 一个时刻 + 一个转变 = 约1200字。紧凑的范围让模型能干净地保持上下文。完成后再编辑，不要等攒了30章才改。

**场景级生成提示词**:
```
以紧密的第三人称POV、现在时态，书写约1200字的场景。
匹配角色圣经中的声音样本。不要总结动作——呈现它。
不要解决核心张力——让场景以开启下一场的节拍结束。

场景简报：[粘贴场景简报]
```

## 5. 角色与世界观一致性

### 5.1 角色一致性问题的根源

LLM固有局限: **"Lost in the Middle"** — 对长上下文中段检索差；**时间线混淆** — 将"将要发生"和"已经发生"混为一谈；**名称幻觉** — 名字被替换；**情绪漂移** — 性格随章节变化。

### 5.2 角色卡模板（可直接复制使用）

```
## 角色卡：[角色名]

### 核心身份
- 戏剧性职务：（例：被流放的皇家抄写员）
- 核心欲望：（最想要什么？）
- 核心恐惧：（最害怕什么？）
- 核心矛盾：（欲望与恐惧之间的张力）

### 基础信息
- 全名：[名称] | 年龄：[年龄] | 外貌：[发色、瞳色、特征性着装]
- 职业：[职业] | 核心特质(3-5个)：[骄傲、脆弱、机智]

### 声音特征
- 说话模式：（短促/冗长/多用比喻/爱用术语）
- 口头禅： | 禁忌词汇： | 语调密度：（简约/华丽/反讽/抒情）

### 关系图谱
- [角色B]：___（关系），在___场景中暴露了___真相

### 背景故事与弧线
- 背景故事：[3-5句话] | 当前目标：[短期]→[长期]
- 核心冲突：[内在冲突] vs [外在冲突]
- 角色弧线：[从___到___的转变]
- 此刻弧线阶段：□初始 □中点转折 □坠落谷底 □觉醒 □最终对决

### 已知/未知信息
- 目前知道的： | 目前不知道的： | 本情境下绝对不应该知道的：
```

**使用原则**: 1) 每个角色卡控制在300-500字 2) 每个新会话都附上角色卡 3) 角色成长了，更新角色卡 4) 先在小场景中测试再用于正式章节

### 5.3 用AI反向提取角色卡

```
分析以下文本，提取角色[角色名]的完整档案。输出包含：
1. 核心身份（戏剧性职务、欲望、恐惧、矛盾）
2. 声音特征（说话模式、口头禅、禁忌词汇）
3. 关系图谱 4. 弧线状态
5. 已知/未知信息（区分"确定"、"推断"、"不确定"）
不要编造事实。如果不确定，标记为"推断"。

文本：[粘贴章节或全文]
```

### 5.4 对话一致性检查提示

```
分析以下对话的对白一致性。对每个角色：
1. 独特的说话模式是什么？
2. 这段对话是否符合性格背景？
3. 是否有任何台词听起来脱离角色？

角色档案：[粘贴] | 对话：[粘贴]

标记任何角色可能会说"这不是我会说的话"的台词。
```

### 5.5 章节后一致性审查提示

```
阅读以下章节并检查一致性：
1. 行为是否与已建立的性格矛盾？
2. 角色是否拥有不应知的信息？
3. 时间线是否正确（无未来事件污染）？
4. 细节（外貌、物品）是否与前文矛盾？
5. 情感弧线是否合乎逻辑？

前情摘要：[前几章关键事件] | 本章：[本章内容]
```

### 5.6 Novarrium Story Bible 技术

**Logic-Locking一致性强制** — Story Bible作为每章生成时的唯一事实来源。追踪每个角色、地点、关系和剧情线索，每章生成后交叉验证。自建方案：在Claude/ChatGPT Projects中创建角色文档库，每次写作前加载。

### 5.7 世界观构建

**五个层级**: Lv1地理 → Lv2历史 → Lv3文化 → Lv4政治 → Lv5魔法/科技。每个层级AI辅助填充细节并确保内部一致性。

**世界规则台账（必须）**:
```
WORLD RULE: [魔法需要能量源] — 确立于: 第3章
  — 限制: 过度会耗尽施法者 | 例外: 上古法器可不消耗
WORLD RULE: [飞行器限高1000米] — 确立于: 第1章
  — 限制: 以上有电离风暴 | 例外: 军用屏蔽装置
```

**世界观构建提示**:
```
你是一个世界构建专家。基于以下前提：[前提]
请生成：1) 三大核心法则 2) 关键历史事件及其连锁反应
3) 两种对立的文化/派系及核心价值观
4) 一个普通人的日常生活描述
5) 这个世界尚未被探索的三个谜团
确保每一部分相互关联。
```

**世界一致性检查**:
```
基于已建立的世界规则：[粘贴世界规则台账]
分析以下场景是否违反任何规则：[粘贴场景]
如果发现不一致，标记并建议修正。
```

## 6. 长篇上下文管理

### 6.1 上下文窗口的现实

|------|---------|---------|
| Claude Sonnet 4 | 1M token | ~650K |
| Claude Opus 4 | 200K token | ~140K |
| GPT-5 | 400K token | ~260K |
| Gemini 3.0 Pro | 2M token | ~1.2M |

> 关键认知: 所有模型在达到宣称限制的30-40%前就会出现性能下降。"Lost in the Middle"仍然存在——两端表现好，中间差。窗口大不等于记忆好。

### 6.2 四层记忆架构

```
层级1：项目知识库（持久化，跨会话）→ 角色卡、世界观、大纲、风格指南 = "源真相"
层级2：场景简报（单次会话内）→ 只含本场景信息，隔离式防剧情溢出
层级3：章节开头锚定（每章前两句）→ "谁、在哪儿、刚发生什么"
层级4：定期审计（每10-15章一次）→ 丢给Claude 200K审查一致性
```

### 6.3 上下文管理五大策略

**策略1：分层压缩** — 每章结束后: 章节摘要 → 提取关键事实和角色状态 → 维护"故事状态"文件（每章一行）→ 下章用摘要而非全文。

**策略2：场景级上下文** — 仅提供当前场景的Codex条目、前2-3个场景摘要、当前POV角色档案。

**策略3：连续性台账** — 轻量级Markdown数据库，每章更新关键事实，只注入最新台账（200-500词）。

**策略4：滑动窗口** — `Chapter N = [Chapter N-2摘要] + [Chapter N-1摘要] + [Chapter N节拍] + [全局台账]`

**策略5：多会话管理** — 每章用新会话（防上下文腐败）。会话包含：项目简报 + 台账 + 角色档案 + 前情提要。完成后提取关键事实加入台账。

### 6.4 章节开头锚定技巧

每章开头写1-2句锚定句，同时服务于AI和读者：

```
[角色名]站在[地点]。[天气/时间/氛围]。距离[上一章关键事件]已经过了[时间]。
```

示例：*林晓站在档案馆潮湿的地下室里。荧光灯管发出微弱的嗡鸣。距离她发现那份伪造的中世纪手稿已经过了三天。*

这自然为AI注入上下文，即使记忆窗口有限也能保持连贯。

### 6.5 定期审计提示词（每10-15章一次）

```
审查以下章节的角色一致性、时间线错误和未解决的情节线。

具体要求：
1. 列出每个引入的角色及首次出现的章节
2. 找出角色知识不一致的地方
3. 列出每个对读者的承诺（悬念/铺垫/弧线设置）及是否已兑现
4. 标记POV滑移的场景和时间线不一致之处
5. 建立时间线（如需要）

章节文本：[粘贴10-15章]
```

### 6.6 JP LeBlanc 实战策略（80,000词验证）

```
每场景提示 = [系统消息:角色/世界/风格] + [6,000词风格指南]
  + [前4个场景全文] + [完整故事进展 1K→80K词]
  + [场景描述] + [额外指令]

问题: 提示越长越贵
当故事超40,000词后: 将"完整故事进展"替换为"每章两段摘要"
```

## 7. 完整工作流

### 7.1 全流程（8-12周完成初稿）

```
阶段 1: 准备期 (第1周)
├── 前提开发: AI头脑风暴3-5个高概念，选定方向
├── 角色开发: 创建主要角色档案，让AI"面试"角色
└── 世界观构建: AI辅助填充细节，建立世界规则台账

阶段 2: 大纲期 (第2周)
├── 结构规划: 选择框架，AI生成大纲，手动重组优化
└── 场景规划: 每章2-3个场景节拍，绑定Codex条目，建立连续性台账

阶段 3: 写作期 (第3-8周)
├── 每周4-6章，每章: 加载台账→粘贴节拍→AI初稿→手动编辑→一致性检查→更新台账
└── 每5章一次大局审查

阶段 4: 编辑期 (第9-10周)
├── 大局编辑: AI分析节奏、结构、弧线
├── 逐章编辑: AI发现不一致、AI味、逻辑漏洞
└── 对话审查+节奏分析

阶段 5: 打磨期 (第11-12周)
├── 逐行润色、语法检查、伏笔检查
├── Beta读者反馈整合
└── 生成封面文案/简介
```

### 7.2 每日高效流程

```
[5min] 加载上下文 → [2min] 准备节拍(3-5关键事件+情感状态)
→ [5min] AI生成(300-600词) → [15-20min] 手动重写(保留结构+自己声音)
→ [3min] 一致性检查+更新台账

总计每场景约30分钟。每日2-3场景 = 60-90分钟。每周6,000-9,000词。
```

### 7.3 多模型协作工作流

```
准备: Claude Opus → 角色圣经、世界观圣经
大纲: GPT-5 → 幕结构+章节级大纲 | Claude Opus → 场景级节拍
起草: Claude Opus / Sudowrite Muse → 逐场景撰写
修订: GPT-5 → 情节逻辑 | Claude Opus → 段落润色 | Gemini → 全稿审计
最终: 人类 → 合成、朗读、定稿
```

**双工具协同**: 通用聊天机器人做创意（头脑风暴、角色开发、困难场景），专业平台做结构化（Codex/Story Bible存储、追踪、生成）。

### 7.4 修订与编辑层级

| 阶段 | AI参与度 | 核心任务 |
|------|---------|---------|
| 1. 结构编辑 | 高 | 检查情节漏洞、节奏问题、角色弧线 |
| 2. 段落重写 | 中 | 扩写平淡、压缩冗长、调整语气 |
| 3. 行级润色 | 低 | 消灭AI味词汇、强化感官细节 |
| 4. 通读校对 | 极低 | 人声合成、朗读检查、最终打磨 |

> 社区共识：AI在阶段1-2最有用，阶段3-4必须以人为主。Final polish必须人工完成。

**精准修订提示**（不要笼统说"修改这一章"）:
```
修订第X章，第Y段：
问题：1) 第2段太抽象——加具体实例 2) 第4-5段过渡突兀——加桥接句
3) 结论像总结——重写为推进力 4) 语气太正式——放松到对话风格
保留：主要论点、开场钩子、三个要点结构。长度：保持约800字。
```

### 7.5 "软件工程化"写作系统

**核心思路**: 写小说 = 软件工程。知识库=源真相，角色卡=对象定义，场景简报=函数参数，生成-修订=测试驱动开发。

**Canon Hierarchy**（矛盾时谁胜出）: `世界设定 > 时间线 > 角色 > 情节 > 风格`

**文件架构**:
```
project/knowledge-base/  ├── beat_sheet.md  ├── world_rules.md
├── characters.md  ├── style_and_pov.md  └── story_progress.md
project/chapters/  └── chapter-01.md...   +  blacklist.md  +  system-rules.md
```

**生成—修订循环**: 每章3-8次迭代:
```
初稿生成 → 风格精炼 → 角色一致性检查 → 情节逻辑验证 → 最终打磨 → 重复
```

## 8. 中文写作实战

### 8.1 中文创作的特殊挑战

| 问题 | 解决方案 |
|------|---------|
| AI味问题 | 国外模型中文语料仅5%，生成"虽然...但是""总而言之"等AI味明显，需黑名单+风格约束 |
| 上下文消耗大 | 中文字符≈2-3 tokens，实际可写章节比英文少30% |
| 网文节奏 | AI默认偏西式，提示词中明确"中国网文节奏" |
| 古风文风 | 文心一言有优势；Claude需配合古文语料 |
| 平台限制 | 晋江禁止AI内容，番茄有AI协议争议 |

### 8.2 国内工具混搭方案

| 环节 | 推荐工具 | 理由 |
|------|---------|------|
| 主线生成 | 笔灵AI | 一键写全篇、爆款模板 |
| 爽文桥段 | 蛙蛙写作 | 网文优化最好，反AI检测 |
| 人物心理 | Claude | 中文散文质量最高 |
| 古风润色 | 文心一言 | 诗词典故语料充分 |
| 逻辑大纲 | Kimi/ChatGPT | 结构化能力强 |
| 宏大设定 | 通义千问 | 稳扎稳打，适合国产化风格 |

**混搭策略**: 笔灵生成主线 → Kimi梳理大纲 → Claude/文心一言润色场景

### 8.3 开源中文本地化工具

- **NovelForge**（GitHub）：知识图谱一致性、DSL上下文注入、万字级长篇
- **MuMuAINovel**（Docker部署）：本地优先、角色卡+关系图、多模型切换

### 8.4 "展示不叙述"与AI用词黑名单

**问题**: AI训练数据使它倾向于总结而非呈现。它会写"她很紧张"，而不是"她来回踱步，指甲在掌心掐出月牙形的印子"。

**基础版提示**:
```
写一个场景：[简述]。使用"展示不叙述"技巧。
通过角色的动作、感官感知和内在想法来呈现。
不要总结事件。让故事如同角色亲历一般展开。
```

**进阶版——嵌入角色卡**:
```
使用以下角色卡。写一篇500字的场景，其中[角色名]被其秘密在意的人指控背叛。
一致性测试：保持角色声音规则可见；通过行为呈现恐惧，不通过解释；
不要让角色说出ta还不知道的信息；以符合当前章节范围的选择结束场景。
场景写完后，列出任何可能与角色卡矛盾的行或动作。
```

### 8.5 AI用词黑名单（在AI开始写作前声明禁止）

| 类别 | 例子 |
|------|------|
| **过滤动词** | felt, noticed, saw, heard, realized, thought, knew, wondered, seemed, appeared, began to, tried to |
| **陈词滥调** | heart skipped a beat, cold as ice, jaw dropped, blood ran cold, knot in his stomach |
| **模糊语** | essentially, generally, typically, almost, kind of, sort of, a bit |
| **AI固定搭配** | let out a breath he didn't know he was holding, a shiver ran down her spine, a wave of [emotion] washed over him |

### 8.6 展示 vs 叙述对照表

| 叙述（不要） | 展示（要） |
|-------------|-----------|
| 她很紧张 | 她来回踱步，指甲在掌心掐出月牙形的印子 |
| 他很生气 | 他的指关节捏得发白，声音却异常平静 |
| 房间很旧 | 地板在脚下吱嘎作响，墙纸像枯叶般卷曲脱落 |
| 他感到害怕 | 他缩进被子里，攥紧床单，屏住呼吸 |
| 她很高兴见到他 | 她嘴角不自觉地扬起，但很快又压了下去 |

### 8.7 去AI味的8个技巧

1. 用更强的AI工具（Claude > GPT-4 > GPT-3.5）
2. 提示词中明确"使用强动词，避免副词"
3. 加入具体感官细节（AI默认缺乏个人体验）
4. 短句+不规则句式（AI倾向于规整长句）
5. 加入文化特定引用（AI用西方比喻多）
6. 使用MECE原则防止AI重复
7. 让AI先复述你的理解再输出
8. 最终输出必须人工重写

## 附录A: 伦理准则（核心5条）

1. **不替代作者**: AI输出当作初稿，用自己声音重写。文字和思想应该是你自己的。
2. **事实核查**: 彻底审查AI输出的事实准确性和文化偏见。
3. **披露**: 在版权注册中披露AI生成内容，遵守平台/合同的AI政策。
4. **不逐字复制**: 不要直接发布未经编辑的AI输出。
5. **保存记录**: 保存创作过程的记录。

## 附录B: 社区验证的最佳实践

### ✅ 必做
1. 建立角色圣经再写第一章——最高杠杆率的投资
2. 按场景写，不按章写——每个场景独立管理上下文
3. 每次生成前注入场景简报——防止剧情溢出
4. 每章开头写锚定句——同时服务于AI和读者
5. 每10-15章做一次一致性审计
6. 保存所有角色卡和设定的版本历史
7. 多模型分工协作

### ❌ 避免
1. 不要一次把所有信息塞给AI——信息过载比不足更糟
2. 不要接受第一次输出——3-8次迭代是常态
3. 不要在同一个会话里无限续写——上下文会腐败
4. 不要依赖单一模型——每个模型都有盲区
5. 不要跳过最终的人工合成

## 附录C: 十大常见陷阱速查

| 陷阱 | 表现 | 解决方案 |
|------|------|---------|
| AI味过重 | "总而言之""不可否认"泛滥 | 风格表+强动词约束 |
| 角色漂移 | 性格在章节间变化 | 每章前加载角色档案 |
| 未来剧透 | 提前透露未发生事件 | 时间线感知提示 |
| 重复词汇 | 特定词反复出现 | 维护禁忌词清单 |
| 逻辑跳跃 | 角色随机传送/时间线错乱 | 精确位置+时间约束 |
| 名字幻觉 | 角色名被替换 | 提示中强调名称 |
| 信息倾泻 | 大段说明性文字 | 要求"展示而非告知" |
| 平淡对话 | 所有角色说话方式相同 | 给每个角色说话风格 |
| 剧情惰性 | 场景没有推进剧情 | 每场景必须有变化 |
| 成本失控 | API费用超预算 | 缓存+批量+选择性AI |

### 提示词调试流程

```
AI输出不符预期 →
├── 检查1: 提示是否明确？给同事看能否看懂？
├── 检查2: 上下文足够？提供了角色/设定/前情？
├── 检查3: 约束清晰？有"不要做什么"的否定指令？
├── 检查4: 示例有效？提供了期望输出范例？
└── 检查5: 模型正确？Claude散文好、GPT对话好、DeepSeek逻辑好
```

### 反AI检测技巧

1. **词汇黑名单** — 从一开始禁用AI常用短语
2. **节奏变化** — AI倾向固定段落长度，人工打乱
3. **不完美** — 添加有意为之的不规则、口语化表达
4. **具体细节** — 替换AI泛化细节为具体、独有、看似无关的细节
5. **朗读测试** — 读出声，标记任何"不像人会说的"
